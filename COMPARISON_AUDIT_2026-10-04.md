# KeySwitch 3.1.1 и Keyray: сравнительный аудит

Дата: 4 октября 2026 года. Метод: две независимые оценки — `/root/visual_audit` (A, дизайн) и `/root/code_audit` (B, технический аудит). Оценка A была завершена до получения результатов B. Код и настройки приложения не изменялись.

## Вывод

KeySwitch уже решает основную задачу локального исправления русской и английской раскладки. Его следующая ступень — надёжная установка, сохранность пользовательских исключений и понятные ручные действия. Увеличивать число функций до устранения этих проблем не рекомендуется.

Интерфейс выглядит как нативное приложение macOS. Полный визуальный редизайн не нужен: основные проблемы находятся в названиях, обратной связи и контекстной роли двойного Shift.

Keyray оценён по [официальному сайту](https://www.keyray.ru/) и иллюстрациям возможностей, а не по установленному приложению. Заявленные возможности не равны проверенной точности или совместимости. Сравнительного теста движков не проводилось.

### Визуальная рекомендация

Сохранить светлые нейтральные поверхности, системную типографику и сдержанный акцент. Убрать повторные объяснения режима, уменьшить число крупных служебных карточек, а пример представить как короткую цепочку «ввод → результат». После первого успешного знакомства пример можно сворачивать.

A/Я-иконка объясняет языковое переключение, но состоит из трёх отдельных элементов: двух клавиш и стрелок. Следующий вариант должен иметь один более цельный силуэт. Проверять узнаваемость в 16–32 px, а не только на большом изображении. Значок в строке меню сейчас — системная клавиатура; его состояния «пауза», «нет доступа» и «ошибка запуска» следует различать. Это рекомендация по исходникам: раскрытое системное меню не удалось осмотреть живьём.

У сайта Keyray можно взять наглядность примеров результата и узнаваемость знака. Светящиеся иллюстрации лендинга не стоит переносить в настройки рабочей утилиты. Иллюстрации на сайте не дают основания оценивать удобство установленного Keyray.

### P1: устранить в первую очередь

1. **Установка из README ссылается на отсутствующее имя пакета.** `scripts/install.sh:5` скачивает `KeySwitch.pkg`, а Release содержит `KeySwitch-3.1.1.pkg`. Решение: выбирать установочный asset через GitHub API либо публиковать стабильное имя. Приёмка: команда README скачивает пакет текущего релиза; проверка выполняется при выпуске каждой версии.
2. **Пользовательское исключение слова может потеряться.** Поле заполняется при открытии раздела (`SettingsWindowController.swift:468`). HUD добавляет слово напрямую (`KeyboardMonitor.swift:274`), поле не синхронизируется, а сохранение заменяет весь список (`SettingsWindowController.swift:1030`). Закрытие окна вызывает сохранение. Решение: сохранять только реальные изменения поля, синхронизировать внешние добавления и разрешать конфликт без потери слов. Приёмка: открытый раздел «Опечатки» не теряет добавление из HUD при смене раздела или скрытии окна. Сценарий выведен по коду; живого воспроизведения в этом аудите нет.

### P2: ясность и согласованность

3. **Разные правила исключений приложений.** Монитор проверяет точный ID и строковый префикс (`KeyboardMonitor.swift:380`), меню — точное совпадение (`AppDelegate.swift:221`). Решение: единый matcher; наследуемые исключения показывать явно, если они действительно нужны.
4. **Двойной Shift имеет три контекстных роли.** Рекомендация: раздельные настраиваемые команды смены раскладки, принятия подсказки и отмены. До этого показывать точное текущее действие в подсказке. Отмена после следующего ввода сейчас недоступна намеренно: расширять её можно только с проверяемым контекстом.
5. **Общий статус не описывает доступность текущего поля.** «Исправление включено» означает готовность мониторинга, но не совместимость каждого редактора. Нужна локальная причина пропуска: приложение исключено, защищённое поле, недоступный контекст. Не показывать постоянные всплывающие сообщения при каждом вводе.
6. **Лишние элементы и неоднозначные названия.** Уточнить названия из таблицы, сократить повторные инструкции, заменить fallback-иконки приложений: контурный квадрат выглядит как чекбокс. В меню показывать статус первой строкой, обслуживание отделить от ежедневных действий.
7. **Задержки глобального ввода требуют измерения.** Event tap работает на main run loop, содержит AX-проверки и синхронный NSSpellChecker. Это архитектурный риск, а не воспроизведённый лаг. Нужны замеры холодного/прогретого словаря и медленных полей. При переносе работы сохранять повторную проверку контекста перед заменой.
8. **Фокус при перестройке секции требует проверки.** Изменение режима пересоздаёт содержимое. Проверить Tab и VoiceOver, обновлять описание без потери текущего контрола. Нарушение фокуса не воспроизведено.

### P3: отделка и документация

9. Собственный синий акцент и вторичный серый не полностью следуют системному accent/Increase Contrast. Проверить семантические цвета в обеих темах.
10. README показывает устаревшую версию и названия разделов; RELEASE_3.1.1.md описывает прежнюю недоступность публикации, PRODUCT.md — старую точку проверки. Это исторические сведения, которые надо отделить от текущего статуса.

P0 в рамках осмотра не обнаружены. Это не гарантия отсутствия ошибок глобального ввода.

## План развития

| Этап | Содержание | Проверяемый результат |
|---|---|---|
| 1. Надёжность | Установочная ссылка, сохранение слов, единые исключения, матрица внешних редакторов | Установка проходит, слова не теряются, меню соответствует фактической работе |
| 2. Ясность | Команды Shift, статусы, названия, компактные объяснения, помощь при первом запуске | Пользователь понимает, что произойдёт и почему исправление пропущено |
| 3. Полезные ручные функции | Настраиваемые сочетания, выделенный текст, смена регистра, словарь и пользовательские пары | Можно исправить собственные имена/термины и уже введённый фрагмент |
| 4. Отделка | Узнаваемые маленькие иконки, темы, focus/VoiceOver, документация | Интерфейс последователен и доступен |
| Позже | Сокращения; затем при отдельном решении голос, AI, новые ОС | Каждая функция имеет отдельный сценарий и границы приватности |

Порядок команд для UX-работы: harden → clarify → distill/onboard → shape для новых функций → optimize/adapt по результатам измерений → audit → polish. Исправления установщика и языковой логики требуют обычной разработки и release-check; UX-команды сами по себе не заменяют тестирование.

Не рекомендуется сейчас добавлять автопродолжение списков и автоматическую капитализацию без отдельной проверки конфликтов с редакторами. Исправление двух заглавных должно защищать имена и сокращения вроде API, iPhone и OpenAI.
